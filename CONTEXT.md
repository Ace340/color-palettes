# Color Palettes — Domain Glossary

## Core Concepts

### Palette
A collection of exactly 5 colors, each assigned a named role. The atomic unit of the application. A palette has no name, description, or metadata in MVP — it is purely its five colors.

The five roles are:

| Role | Purpose | CSS Variable |
|------|---------|-------------|
| Primary | Brand identity, main actions | `--color-primary` |
| Secondary | Supporting elements | `--color-secondary` |
| Accent | Highlights, call-to-action | `--color-accent` |
| Background | Page/canvas background | `--color-background` |
| Surface | Cards, panels, elevated areas | `--color-surface` |

### Harmony
A method for generating a palette from a single base color. Six modes are supported: complementary, analogous, triadic, split-complementary, tetradic, and monochromatic.

### Surprise Me
One-click palette generation that picks a random vivid base color (high saturation, mid-range lightness) and applies a randomly weighted harmony mode. Produces a complete 5-role palette in a single interaction. Foundation colors adapt to the current theme — light backgrounds in light mode, dark backgrounds in dark mode. The primary entry point for new users; also available in the Generator section for repeat use. One level of undo is available to recover the previous palette.

Harmonies fill palette roles in two stages:
1. **Identity colors** (primary, secondary, accent) — generated by the harmony algorithm from the base color
2. **Foundation colors** (background, surface) — derived by applying lightness/saturation variations to produce a low-saturation, high-lightness base and a slightly elevated surface

Users can override any slot manually after generation. Roles are structural — they govern how harmonies are generated and how colors export.

### Palette Persistence
No database. Palettes are stored in two complementary ways:

- **localStorage**: Holds up to 20 saved palettes. Users work on one active palette at a time and can save/load from their history.
- **URL encoding**: The active palette is encoded in the URL (`?p=FF5733-00AACC-EE4422-F0F0F0-FFFFFF`) for one-click sharing. Hyphen-joined hex without `#` prefix, roles in fixed order. Invalid/missing values fall back silently to the default starter palette. Only represents a single palette — the currently active one.

## Application Scope

### Palette Creation (Primary)
Build palettes from scratch using color picking, harmony generation, and AI mood-based generation.

### Image Extraction (Secondary)
Upload an image and extract dominant colors into palette slots using colorthief (client-side, median cut algorithm). Extracted colors are smart-mapped to roles: most vivid (by chroma) → accent, lightest → background, second lightest → surface, remaining by dominance → primary/secondary. Users can adjust after extraction.

### Export (Secondary)
Export a palette in multiple formats (CSS Variables, Tailwind Config, JSON, URL). Copy-to-clipboard for all formats; download-as-file for CSS Variables, Tailwind Config, and JSON. SVG and PNG export are deferred to a later phase.

## Application Structure

Single-page application on `/`. The page has a sticky Navbar with jump links, a Hero section, and three content sections (Generator, AI Generator, Live Preview) stacked vertically with generous spacing. Harmony controls live inside the Generator section as a compact toolbar beneath the swatches. Image extraction, export, and saved palette history are accessed via slide-in panels (Shadcn Sheet) triggered from the Navbar. URL changes only for sharing (`?p=...`).

The app UI defaults to light mode (slightly off-white background) with a dark mode toggle in the Navbar. On mobile, the Navbar collapses into a hamburger menu. Palette colors appear only in the swatches and the live preview panel — the app chrome stays neutral and readable regardless of the palette being edited.

### AI Mood Generation
Users describe a mood in natural language. The prompt sent to the model includes role semantics (e.g., "background should be low-saturation and high-lightness, accent should be the most vivid"). The model is instructed to return structured JSON mapping roles to hex values. The server action validates the response with Zod, retries once on failure, and returns a graceful error if it still fails.

### Color Picker
Each palette slot opens a color picker (react-colorful) in a popover. A visual saturation/brightness square plus hue slider for quick selection, with HSL number sliders below for precise fine-tuning. All values round-trip through hex as the source of truth.

### Contrast Indicators
Passive WCAG contrast ratio badges shown on key color pairings (primary-on-background, accent-on-background, surface-on-background). Color-coded green/yellow/red by AA/AAA thresholds. No enforcement — purely informational.

### Palette Preview
Two-part display: a row of color swatches for editing (click to open picker), plus a live preview panel rendering a mock card/dashboard component using the palette's five colors. On first visit, a starter palette is pre-loaded so the app feels alive immediately.

### Color
A single color stored as a hex string (e.g., `#FF5733`). chroma-js is used on demand for all color operations — conversions, harmony calculations, contrast checking. Hex is never stored alongside other representations; it is the sole source of truth.
